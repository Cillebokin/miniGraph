# MG-009～MG-011 性能基线

记录 miniGraph 在本机 Windows Release 构建下的首次性能基线，用于后续同一环境的前后对比。该数据不是性能承诺，也不代表其他硬件、驱动或桌面合成环境。

## 环境

| 项目 | 实测环境 |
| --- | --- |
| 操作系统 | Windows 10 Pro 26H2，Build 26300.9457 |
| CPU | AMD Ryzen 7 9700X，8 核 / 16 线程 |
| 内存 | 31.11 GiB |
| Qt | Qt 5.12.10，`msvc2017_64` 套件，ABI `x86_64-little_endian-llp64` |
| C++ 编译器 | Visual Studio 2022 MSVC 19.44.35228，x64；本机未安装 v141 编译器 |
| 构建类型 | Release，`/O2 /MD`，定义 `NDEBUG` |
| Qt 平台 | `offscreen`；画布以 QPainter/QImage 栅格路径绘制 |
| 视口 | 1280×720 逻辑像素，DPR=1.00 |
| 测量统计 | 每项预热 3 批，测量 31 批；记录每批内单次操作均值的中位数与线性插值 P95 |

构建使用 Qt 5.12.10 的 `msvc2017_64` 库和本机可用的 VS2022 MSVC 19.44 编译器。报告如实记录两者版本；本次 Release 基准程序、动态库和 Release QtTest 均成功构建并运行。

### MG-009：完整画布帧

打开网格、坐标轴和标尺，实体场景采用约 67% 曲线类型（圆弧、圆、椭圆、样条）。测量完整 `CanvasView` 渲染；实体数量分别为 100、1,000 和 5,000。

| 实体数 | 帧中位数 (ms) | 帧 P95 (ms) | 每批迭代数 |
| ---: | ---: | ---: | ---: |
| 100 | 1.142061 | 1.292868 | 100 |
| 1,000 | 2.237460 | 2.530625 | 10 |
| 5,000 | 7.172750 | 10.000825 | 2 |

1280×720、DPR=1 时，三张 `Format_ARGB32_Premultiplied` 图层缓冲估算为 **11,059,200 字节（约 10.55 MiB）**。这是像素存储容量估算，不是进程 RSS 或每帧新增分配量。

#### MG-010 曲线密集场景定向剖析

在同一 Release/offscreen 环境下，单独运行 5,000 图元的点击命中/未命中剖析；曲线场景的圆弧、圆、椭圆、样条合计约 67%。每个测量批次发送 2 次点击，预热 3 批、测量 31 批。每次点击实际触发 2 次 `HitTestItem`，分别来自鼠标按下和释放。

为控制计时器对逐实体循环的扰动，实体查询、选择路径生成和逐段测距的阶段耗时对每 36 个实体中的 6 个实体采样并乘以 6 作估算；ItemId 列表读取、`HitTestItem` 总耗时和点击事件耗时由计时器直接测量。场景实体数、图元类型数量、生成路径数量和路径点数量为精确计数。分阶段采样值是分层抽样估值，不是逐项精确耗时。完整结果见[定向剖析 CSV](MG-010曲线密集场景定向剖析-2026-10-10.csv)。

| 命中检测阶段 | 点击命中中位数 / P95 (ms) | 点击未命中中位数 / P95 (ms) |
| --- | ---: | ---: |
| ItemId 列表读取 | 0.000025 / 0.000050 | 0.000025 / 0.000063 |
| 实体查询 | 0.115950 / 0.125325 | 0.115950 / 0.122175 |
| 选择路径生成 | 1.832100 / 1.873125 | 1.818900 / 1.898100 |
| 路径逐段测距 | 0.825150 / 0.857850 | 0.817650 / 0.858000 |
| `HitTestItem` 内部总耗时 | 2.740925 / 2.812275 | 2.740875 / 2.831437 |

剖析构建中的点击事件中位数为命中 **5.491600 ms**、未命中 **5.483350 ms**，与原始基线接近；该构建包含诊断代码，这组端到端数值仅用于对照，不替代无剖析宏的基线。更关键的是，命中与未命中几乎相同：当前实现会遍历全部 5,000 个实体，并在测距前为每个实体收集选择路径；不是“命中目标后立即结束”。

按实体类型拆分的代表性中位数如下，路径生成和测距列均为该类型在一次 `HitTestItem` 中的合计估值：

| 类型 | 每次检测实体数 | 生成路径点数 | 路径生成 (ms) | 路径测距 (ms) |
| --- | ---: | ---: | ---: | ---: |
| Point | 834 | 834 | 0.081300 | 0.020700 |
| Line | 834 | 1,668 | 0.112650 | 0.031350 |
| Arc | 833 | 2,499 | 0.167700 | 0.058200 |
| Circle | 833 | 14,161 | 0.289800 | 0.331500 |
| Ellipse | 833 | 14,161 | 0.311250 | 0.324450 |
| Spline | 833 | 2,499 | 0.865500 | 0.057600 |

当前数据给出的热点方向很明确：

- 路径生成约占 `HitTestItem` 内部总耗时的 **67%**；其中 Spline 路径生成约 **0.866 ms**，约占路径生成阶段的 **47%**。它只生成约 3 个采样点/实体，耗时仍显著高于其他类型，值得后续单独检查样条离散算法。
- 圆和椭圆各生成约 17 个路径点/实体；两者测距合计约 **0.656 ms**，占路径测距阶段约 **80%**，主要反映了长离散路径的逐段距离计算量。
- 实体查询约 **0.116 ms**，ItemId 列表读取可以忽略；当前首要成本不是容器查询，而是全量路径生成与曲线段测距。

本次只增加可选基准诊断，没有修改正式构建中的绘制、选择或命中算法。剖析接口仅在 `CONFIG+=performancebench` 构建下编译，统计数据放在现有私有实现对象中，不改变 `CanvasView` 的对象布局。

均测量包含 `CanvasData` 的完整画布帧。动态命令在每帧调用时生成；图片命令每次重建 `QImageReader` 并读取同一张 256×256 PNG，文件缓存为暖状态。

## 运行与复现

基准为独立可选 qmake 子项目；未设置 `CONFIG+=performancebench` 时不会加入常规构建。核心代码位于 `benchmarks/CanvasPerformanceBenchmarks.cpp`。

```bat
call "<VS2022安装目录>\VC\Auxiliary\Build\vcvars64.bat"
cd /d "<miniGraph项目目录>\build\perf_baseline_msvc2017_release"
"<Qt5.12.10 msvc2017_64目录>\bin\qmake.exe" ..\..\MiniGraph.pro -o Makefile CONFIG+=release CONFIG+=performancebench
nmake /f Makefile sub-benchmarks-PerformanceBenchmarks-pro
set QT_QPA_PLATFORM=offscreen
set QT_QPA_PLATFORM_PLUGIN_PATH=<Qt5.12.10 msvc2017_64目录>\plugins\platforms
set QT_PLUGIN_PATH=<Qt5.12.10 msvc2017_64目录>\plugins
set PATH=<Qt5.12.10 msvc2017_64目录>\bin;<构建目录>\bin;%PATH%
bin\MiniGraphPerformanceBenchmarks.exe
```

只运行 MG-010 5,000 图元曲线场景的命中/未命中定向剖析时，使用：

```bat
bin\MiniGraphPerformanceBenchmarks.exe --mg010-profile
```

逐场景原始数据：[MG-009～MG-011性能基线 CSV](MG-009至MG-011性能基线-2026-10-10.csv)；MG-010 定向剖析数据见[单独 CSV](MG-010曲线密集场景定向剖析-2026-10-10.csv)。本次无性能宏的 Release 构建成功，QtTest **180 passed、0 failed、0 skipped**；QtTest 输出了缺少 Qt `lib/fonts` 目录的字体提示，测试仍正常完成。

## 解释边界

- 这是单机、单次基线，用于后续在同机同环境对比；不设人为性能门槛。
- `offscreen` 不包含实际窗口系统、显示器刷新和桌面合成器延迟；真实交互体验仍需在目标用户环境验证。
- 点/线与曲线场景的图元分布、曲线离散精度会影响结果；基线只代表此基准程序构造的场景。
- 数据支持“实体数和曲线比例会明显影响当前遍历路径耗时”这一观察，但不足以承诺最大图元数、帧率或特定设备上的响应时间。
- 基准不修改 Canvas 运行时绘制、选择或捕捉算法；优化应以目标硬件需求和重复测量为依据。
